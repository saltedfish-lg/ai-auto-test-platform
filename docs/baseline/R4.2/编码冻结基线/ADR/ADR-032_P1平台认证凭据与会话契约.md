# ADR-032：P1平台认证、凭据与会话契约

- 状态：Accepted
- Release：`PDBR-2026.08.07-R4.2`
- 上游：R4.1 `BR-USER-0001..0087`、`CRD-001`、`CRD-012`、`TCK-001..003`、`SEL-038`
- 同步契约：六份核心YAML、SYSTEM_DESIGN、Authentication Contract、V5 Migration、OpenAPI、State Owner Registry、Acceptance Closure

## 背景

R4.1声明了Bearer JWT和Argon2id，但没有登录闭环、平台用户凭据物理模型、Refresh/撤销生命周期、admin初始秘密交付以及ACTIVE与ENABLED/NORMAL的唯一映射，导致P1无法在不发明正式语义的情况下编码。

## 决策

1. 平台Browser认证采用短期RS256 Bearer Access JWT与服务端持久化、可撤销、每次刷新轮换的Refresh Session。
2. Access Token有效期15分钟、时钟偏差60秒；Refresh Session绝对有效期7天。权限不写入JWT，每个受保护请求实时校验用户、凭据版本、Session状态与正式RBAC关系。
3. Browser仅在运行时内存保存Access Token；Refresh Token只进入`HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth` Cookie。localhost开发可关闭Secure，其他环境禁止。
4. 平台密码凭据使用独立`atp_platform_user_credential`，Refresh Session使用`atp_auth_refresh_session`；不得复用测试账号凭据或`extension_json`。
5. 密码哈希采用Argon2id v19，m=65536 KiB、t=3、p=1、salt=16字节、hash=32字节，使用PHC字符串和成熟库；成功验证旧参数时升级rehash。
6. 密码长度12至128，至少包含字母和数字；不强制特殊字符和定期过期；拒绝首尾空白、与用户名相同及常见弱密码；V1不保留历史，只禁止等于当前密码。
7. admin固定用户名仍为`admin`。初始化必须使用无回显交互输入，或通过`ATP_BOOTSTRAP_ADMIN_PASSWORD_FILE`读取部署秘密；禁止命令行明文、固定默认密码及初始化输出密码。首次登录强制改密，重复初始化不得覆盖凭据。
8. `atp_user.lifecycle_status=ACTIVE`是唯一“业务启用”状态；旧规则`ENABLED`统一规范化为`ACTIVE`。`NORMAL`是凭据ACTIVE且未被`locked_until`临时锁定的派生安全语义，不新增重复的`security_status`列。
9. 连续15分钟内5次失败触发15分钟临时锁，Owner为CredentialService，不改变用户业务状态。管理员控制的无限期锁继续使用用户`LOCKED`状态；`DISABLED`保持业务停用语义。
10. 登录成功/失败、登出、改密、凭据重置和Session撤销在P1使用不可变审计，不新增无消费者的领域事件；既有用户、admin与角色绑定状态事件继续复用。

## 备选方案与取舍

- 纯短Access Token、无Refresh：实现简单，但页面刷新和撤销体验差，无法满足已冻结的登出与现有会话失效语义，拒绝。
- 长期JWT且权限写入Token：降低数据库查询，但造成实时撤权和用户禁用延迟，拒绝。
- 服务端传统Cookie Session：可撤销，但偏离R4.1已声明Bearer JWT的方向，拒绝。
- 固定默认admin密码或首次启动打印随机密码：自动化方便但泄露风险高，拒绝。
- 独立security_status：表达直观，但与用户LOCKED及失败锁字段形成重复Owner，拒绝。

## 后果

- P1实现必须提供Login、Refresh、Logout、Me和Change Password五个正式Operation。
- 所有Access请求增加用户、凭据版本和Session状态查询；RBAC权限仍实时计算。
- V5是只新增表的兼容Migration，可从R4.1升级，也可参与空库完整安装。
- 本ADR只记录已同步裁决，不独立覆盖核心YAML或工程契约。
